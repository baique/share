# @baique/share —— 局域网共享终端（设计）

日期：2026-09-08
状态：已批准

## 1. 背景与目标

做一个局域网内"聊天室式"数据共享器：任意一台电脑 `npx @baique/share` 启动终端界面，自动通过局域网发现其他在线设备；发一条消息即广播给所有在线设备；可以发文本、发文件；任何在线设备可复制文本、下载文件。

- 目标平台：macOS、Windows（Node CLI，跨平台）
- 运行方式：`npx @baique/share`，启动即用，零配置
- 定位：极简、干净、高性能、单一聊天室

## 2. 已确认的需求边界

| 项 | 决策 |
|---|---|
| 形态 | 终端界面（TUI），非桌面窗口、非网页 |
| 房间模型 | 单一房间，局域网内所有运行者自动进入同一聊天室 |
| 消息保留 | 最近 30 分钟，仅内存，重启清空 |
| 消息内容 | 文本、文件（谁、什么时间、发了什么） |
| 文件交互 | 发送方标识文件，接收方按序号下载 |
| 下载位置 | 启动 share 的当前工作目录，在哪打开就存哪 |
| 身份 | 直接取主机名，不提供任何设置项 |
| 安全 | 无加密、无鉴权（同一局域网内所有运行者可见） |
| 离线消息 | 不做补发；新上线设备从在线节点拉取最近 30 分钟历史 |
| 跨网段 | 不自动发现；提供 `-c <ip>` 手动直连指定 IP（三层互通即可用，覆盖 WiFi↔LAN） |

## 3. 技术选型

| 模块 | 方案 | 理由 |
|---|---|---|
| 运行时 | Node.js ≥ 18（用户环境 25.x） | npx 即 Node 生态 |
| 界面 | Ink（React 渲染终端） | 组件化 TUI，聊天室列表好实现 |
| 局域网发现 | multicast-dns（纯 JS UDP 组播 5353） | 不依赖系统 Bonjour/Windows 服务，跨平台零配置；仅同广播域有效 |
| 节点通信 | Node 原生 `net`(TCP) + `http` | 零第三方依赖，局域网内高性能 |
| 文件下载 | Node 原生 `http` 流式传输 | 直接点对点拉取，不中转 |

## 4. 架构

每台机器运行的进程既是客户端也是服务器，无中心节点：

```
你的机器                         同事的机器
┌─────────────────────┐         ┌─────────────────────┐
│ TUI (Ink)           │   TCP   │ TUI (Ink)           │
│ 消息历史(30min内存)  │◄───────►│ 消息历史(30min内存)  │
│ mDNS 广播/发现       │  UDP    │ mDNS 广播/发现       │
│ HTTP 文件服务        │◄─HTTP──►│ HTTP 文件服务        │
└─────────────────────┘         └─────────────────────┘
```

模块划分（单一职责）：

- **discovery**：mDNS 广播自身身份，监听发现/下线事件（纯 mDNS，不做网段扫描）
- **node-list**：维护在线节点表（昵称/IP/端口/最后心跳）
- **connect**：`-c <ip>` 直连指定 IP：先按约定端口建立连接，握手后拉取历史，纳入在线列表
- **server**：TCP 接收文本与文件元数据；HTTP 提供文件下载
- **history**：内存保存最近 30 分钟消息，提供拉取接口
- **share 核心**：发文本（遍历在线节点推 TCP）、发文件（挂 HTTP + 推元数据）
- **ui**：Ink TUI，消息列表、输入框、下载交互

## 5. 数据模型

### 5.1 节点身份（mDNS 广播内容）

```
type=share, name=<主机名>, port=<TCP端口>, id=<uuid>
```

### 5.2 消息（TCP 载荷，JSON，`\n` 分隔）

```json
{
  "id": "uuid",
  "type": "text | file",
  "from": "主机名",
  "time": 1730000000000,
  "text": "消息内容（type=text 时）",
  "file": {
    "name": "设计稿.png",
    "size": 2400000,
    "url": "http://192.168.1.5:41023/f/a1b2"
  }
}
```

### 5.3 协议命令（TCP 首字段 type）

| type | 方向 | 说明 |
|---|---|---|
| `text` | 广播 | 文本消息 |
| `file` | 广播 | 文件元数据（HTTP URL 指向发送方） |
| `sync` | 请求/应答 | 新设备上线后拉取最近 30 分钟历史（请求带本机已见消息 id，应答返回增量） |
| `bye` | 广播 | 优雅下线通知（兜底仍靠心跳超时） |

### 5.4 心跳与下线判定

- 节点在线判定：mDNS 有 TTL 天然超时 + TCP 连接存活检测双通道
- 设备离线 → 从在线列表移除，TUI 刷新在线数

## 6. CLI 参数

| 参数 | 说明 |
|---|---|
| （无） | mDNS 自动发现同广播域设备 |
| `-c <ip>` | 直连指定 IP（跨网段/兜底）。自动探测约定端口，握手后同步历史并加入列表 |

极简原则：仅此一个可选参数，无配置文件。

## 7. TUI 交互

```
┌────────────────────────────────────────────┐
│  LAN Share — 3 台设备在线                    │
│  [10:32] 王先生-Mac: 大家看下这个方案         │
│  [10:33] 小李-PC: [文件] 设计稿.png(2.3MB)   │
│          按 1 下载 ▸ 下载完成 → ./设计稿.png  │
│                                            │
│  > 粘贴文本或文件路径，回车发送                │
│  ↑/↓ 滚动  q 退出                            │
└────────────────────────────────────────────┘
```

- 底部输入框：输入内容，回车发送
- 输入值是**存在的文件路径** → 识别为文件发送；否则按文本发送
- 文件消息条目分配序号（当前会话中按出现顺序），按数字键下载
- 下载完成后在消息区打印结果：`下载完成 → ./设计稿.png`（当前工作目录）
- 新上线设备自动向在线节点同步最近 30 分钟历史，进来即看到之前内容
- 快捷键：`↑/↓` 滚动消息区，`q` 退出
- 在线设备数实时显示在标题栏

## 8. 文件传输

- 发送方：文件挂到本地 HTTP 服务，URL 形如 `http://<ip>:<port>/f/<id>`，按 id 关联内存中的文件句柄（保留文件名）
- 接收方：拿到 file 元数据后仅展示，不自动下载；按序号触发 HTTP GET，流式写盘到当前工作目录
- 文件名冲突：追加 ` (1)`、` (2)` 后缀
- 传输进度：简单百分比显示（可选，P0 可只显示完成态）

## 9. 错误处理与边界情况

- 文件不存在/已删除：发送方推送前校验，失败提示"文件不存在"
- 下载失败（对方已退出）：提示下载失败，条目保留可重试
- TCP 端口冲突：监听失败时端口 +1 重试，广播用实际端口
- 同一设备重复 mDNS 记录（多网卡）：按 id 去重
- 30 分钟过期消息：定时清理，广播同步时同样过滤

## 11. 测试策略

- 单元测试：history（30 分钟裁剪、增量同步）、node-list（去重/超时移除）
- 集成测试：两个进程实例在同机不同端口互发文本/文件，验证收发与下载（模拟局域网）
- 手工验证：真实局域网 mac + windows 互传
- 不保留测试数据，测试用 `try...finally` 清理临时文件与端口
